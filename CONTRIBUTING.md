# Contributing to Averixa Group

Thank you for your interest in contributing to Averixa Group projects.

We welcome thoughtful contributions that improve the quality, reliability, security, documentation, and functionality of our technology projects.

## How to Contribute

Before making a contribution, please review the repository documentation and any existing issues.

A typical contribution process is:

1. Fork the repository.
2. Create a new branch for your changes.
3. Make your changes.
4. Test your changes when applicable.
5. Write clear and descriptive commit messages.
6. Submit a pull request explaining what you changed and why.

## Issues

If you discover a bug, have a feature suggestion, or identify an improvement, you may open an issue.

When creating an issue, please provide:

- A clear title
- A detailed description
- Steps to reproduce the problem, when applicable
- Expected behavior
- Actual behavior
- Relevant screenshots, logs, or technical information

Please do not include passwords, API keys, access tokens, personal information, or other sensitive data in public issues.

## Pull Requests

Pull requests should be focused and easy to review.

Please:

- Keep changes relevant to the purpose of the pull request
- Explain significant technical decisions
- Update documentation when necessary
- Test changes before submission
- Avoid unrelated modifications
- Follow the existing project structure and coding conventions

## Security Vulnerabilities

Do not report security vulnerabilities through public GitHub issues.

Please follow the instructions in our `SECURITY.md` file for responsible vulnerability reporting.

## Code Quality

Contributions should prioritize:

- Reliability
- Security
- Maintainability
- Clear documentation
- Practical implementation
- Scalable architecture

## Documentation

Documentation improvements are welcome.

Documentation should be clear, accurate, and written so that developers and technical users can understand how the project works.

## Review Process

Submitting a contribution does not guarantee that it will be accepted.

Averixa Group may review, request modifications, approve, or decline contributions based on project requirements, security considerations, technical quality, and long-term maintainability.
